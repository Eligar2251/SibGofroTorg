# Фото загружены, но не видны на сайте — чек-лист

Симптом: загрузка проходит (файл виден в Cloudinary), а на сайте — пустая плитка
или битая картинка. В 99% случаев дело не в Cloudinary, а в том, **как браузер
получает картинку**.

## Как это устроено

1. Загрузка идёт через `POST /api/admin/upload` (или через генератор фото —
   `POST /api/admin/products/[id]/generate-images`). Сервер кладёт файл в Cloudinary
   и возвращает `secure_url` + `publicId`; они сохраняются в `products.image_url`
   и `products.images`.
2. **В браузере картинки должны грузиться только через наш `/media/...`**, а не по
   прямому адресу `res.cloudinary.com`. Причина — политика безопасности
   (`src/proxy.ts`): `img-src 'self' data: blob:`. Внешний хост браузер блокирует,
   и картинка не появляется, хотя с файлом всё в порядке.
3. Перевод наружного адреса во внутренний делает `toSameOriginMediaUrl()`
   (`src/lib/media.ts`): серверные страницы вызывают `localizeMediaDeep()` для
   всех данных, идущих в клиентские компоненты, а админ-компоненты и превью
   оборачивают адрес явно.
4. Дальше работает прокси `GET /media/cloudinary/<путь>`
   (`src/app/media/[...path]/route.ts`): он проверяет путь через
   `buildUpstreamUrl()` (`src/lib/media-proxy.ts`), догружает изображение с
   Cloudinary, кэширует ответ на 30 дней и отдаёт браузеру как свой.

## Куда смотреть по шагам

1. Откройте страницу с картинкой, DevTools (F12) → вкладка Console.
   - `Refused to load the image ... because it violates ... "img-src 'self'"` →
     где-то в код попал прямой адрес Cloudinary. Правильный адрес начинается с
     `/media/cloudinary/`. Исправление: обернуть в `toSameOriginMediaUrl(...)`
     (или отдать данные через `localizeMediaDeep(...)` на сервере).
2. Вкладку Network → фильтр `Img`. Если запросы к `/media/...` отдают `404` —
   прокси не признал путь. Возможные причины:
   - `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` не совпадает с именем облака внутри
     сохранённого URL (см. `ENV_GUIDE.md`). Неверное/лишнее значение — и **все**
     фото начинают отдавать 404, загрузка при этом продолжает работать.
   - в базе лежит URL другого формата (не `<облако>/image/upload/...`), например
     из старого провайдера или из приватного хранилища Supabase.
   Быстрая проверка в консоли браузера на сайте:

   ```js
   fetch("/media/cloudinary/<облако>/image/upload/<путь-как-в-базе>")
     .then((r) => console.log(r.status, r.headers.get("content-type")));
   ```

   `200 image/webp` — прокси жив, проблема в конкретном адресе.
3. В генераторе фото («Конструктор фото»): исходники (фон и картинки элементов)
   грузятся через canvas, поэтому они тоже обязаны идти через `/media`. Ошибка
   показывается прямо в поле — «чужой хост ... блокирует политика безопасности».
4. Картинки «витрины» прайс-листа рисуются через `<canvas>`, поэтому для них
   `crossOrigin="anonymous"` обязателен: `/media` отдаёт `Access-Control-Allow-Origin: *`
   именно ради этого.
5. После замены фото в карточке товара добавьте `?v=<метка>` (см. `docs/DATABASES.md`)
   — браузер кэширует `/media` на 30 дней и может показывать старое фото.

## Что уже поправлено в коде (2026-11-13)

- «Конструктор фото» (`PhotoTemplateGenerator.loadImage`) — грузил фон и картинки
  элементов по прямому адресу Cloudinary, canvas оставался пустым. Теперь через `/media`.
- «Связанные товары» в карточке (`LinkedProductsEditor`) — три `<img>` с
  `imageUrl` без перевода,миниатюры блокировались той же политикой. Теперь через `/media`.
- Страховка: `npm run test:media` включает `tests/media-csp-audit.test.mjs` — он
  проходит по всему `src/` и падает, если в `<img>` снова попадёт фото-поле без
  `toSameOriginMediaUrl`. Если картинку приходится отдавать наружным адресом
  осознанно, поставьте перед тегом комментарий `csp-allow`.

После деплоя старые HTML-страницы из кеша ISR могут ещё содержать прямые ссылки —
помогает перезапуск процесса (`pm2 restart`) и жёсткое обновление в браузере.

## Чего делать нельзя

- Не добавляйте `res.cloudinary.com` в `img-src` CSP: весь смысл `/media` в том,
  чтобы браузер пользователя не ходил в зарубежный CDN (152-ФЗ, скорость, кэш).
- Не сохраняйте в базу `secure_url` без `publicId`: по `publicId` идёт удаление
  старого файла и сборщик медиа-пути.

## Автотесты

`npm run test:media-url` — сопоставление адресов (включая путь «загрузчик →
Cloudinary → /media» и запрет прямых ссылок в конструкторе фото),
`npm run test:media-route` — поведение прокси-роута (404 на чужое облако, 403 на
приватный ресурс, кэш-заголовки).
