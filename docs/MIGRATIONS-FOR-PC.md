# Какие миграции нужны для локальной JSON-копии

**Применять отдельно на каждой Supabase**, с которой этот ПК должен делать
копии: на Beget (#1) и/или supabase.com (#2). Реальные базы в разработке не
изменялись; до применения сделайте PostgreSQL-резервную копию и сначала
испытайте на тестовой базе. Через Supabase Dashboard откройте SQL Editor,
вставьте содержимое выбранного файла и запустите его. Нужны права на создание
функций и триггеров; у self-hosted установки они зависят от конфигурации.

Есть два пути — **выберите один**, не нужно применять оба набора подряд:

1. Для новой базы или если неизвестно, какие старые миграции уже есть:
   `supabase/FULL_DATABASE_MIGRATION.sql`. Это объединённый файл с `schema.sql`
   и всеми `migration_*.sql` проекта, включая обе миграции из пункта 2 и
   экспериментальную миграцию merge. Он уже собран в правильном порядке. Не
   считайте его запуск в неизвестной рабочей базе безусловно безопасным:
   проверьте на копии и сохраните резервную копию.
2. Если все предыдущие миграции проекта **точно уже применены** и требуется
   только функция PC-копирования, последовательно:
   1. `supabase/migration_complete_app_backup.sql` — полный снимок таблиц.
   2. `supabase/migration_pc_incremental_backup.sql` — журнал изменений.

Само применение SQL не включает триггеры слежения. После установки на каждом
используемом источнике владелец в админке выбирает его и нажимает «Подготовить
журнал выбранной Supabase» (на сайте Timeweb — «Подготовить отслеживание
Supabase»). Это глобальное изменение всей базы: триггеры записывают журнал при
изменениях и подготовка может блокировать таблицы. Выполняйте вне рабочего времени
после проверки и следите за ростом журнала. Без этого доступен начальный снимок,
но текущие изменения автоматически не обновляются.

Для текущего сценария не требуются SQL команды для локального JSON, отдельный
сервер БД или `migration_pc_merge_apply.sql` по отдельности: экспериментальный
merge не подключён и синхронизация сейчас не реализуется. Для первой настройки
владельца используйте Supabase Dashboard → Table Editor, а не CLI или ручной SQL.
