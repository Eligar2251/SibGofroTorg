# Три источника БД

Все переменные собраны в `.env.example`. Перенесите свои существующие значения
в `.env` на сервере, заполните `SUPABASE_SECONDARY_*` ключами **вашего VPS**
и перезапустите приложение. Ваши имена `NEXT_PUBLIC_SUPABASE_ANON_KEY` и
`SUPABASE_SERVICE_ROLE_KEY` работают и с новыми ключами `sb_publishable_...` и
`sb_secret_...`. Не публикуйте секреты. Supabase на VPS — это полноценный
Supabase с API (PostgREST), не просто порт PostgreSQL. На обеих базах должна
быть установлена совместимая схема и данные.

При заданном URL в окружении соответствующие ключи также берутся из окружения,
а старые значения из настроек админки не подмешиваются. При отсутствии URL
можно использовать ранее сохранённые в админке параметры. Настройки выбора
хранятся в `SGT_DATA_DIR`; используйте постоянный том Docker и одну экземплярную
установку: локальная JSON-БД и состояние аварийного переключения не рассчитаны
на одновременную работу нескольких независимых процессов или серверов.

В админке откройте **База данных → переключение источника** и выберите
Cloud, VPS или локальную JSON-БД. Перед сменой проверяется доступность;
само переключение **не копирует данные**. Заранее синхронизируйте и проверьте
содержимое целевой базы. При несинхронизированных локальных изменениях переход
на удалённую базу блокируется: выберите целевую базу в разделе синхронизации,
выполните синхронизацию и проверьте ошибки. Не отправляйте изменения в другую
базу, если она не является копией исходной.

При выключенной полной репликации автопереключение сначала пробует другой Supabase, затем локальный файл. При включённой — только локальный файл (см. [полные копии](FULL-BACKUP.md)).
Оно помогает пережить сетевой отказ, но **не является репликацией**. Резерв
может быть устаревшим или пустым: предварительно создайте и регулярно проверяйте
снимки и синхронизацию. После перехода на другой сервер приложение остаётся на
нём до ручного выбора; внесённые там данные автоматически не попадают обратно
на первый сервер. При работе из локальной БД с неотправленными изменениями
автовозврат также приостановлен до синхронизации. При сетевом обрыве результат
записи в удалённую БД может быть неопределённым — проверьте запись до повтора.
Полную непрерывность работы и согласованность транзакций это не гарантирует.

`SGT_DATA_DIR` — каталог на компьютере, где исполняется сервер приложения.
Сайт на VPS не может напрямую открыть `C:/...` или `D:/...` вашего домашнего ПК:
нужно безопасно подключить диск как файловую систему к серверу и настроить
постоянное монтирование, либо запускать сайт на ПК. Если ПК выключен/сеть
недоступна, такой диск не обеспечит бесперебойную работу сайта. Отдельная
функция бэкапа в браузере может сохранять копии на ПК, но не делает его диском
рабочей серверной БД и не работает при закрытом браузере.

Настройка и ограничения полных копий всех таблиц: [FULL-BACKUP.md](FULL-BACKUP.md).
