# Чек-лист задач и фактический статус

Это состояние кода, а не подтверждение настройки или развёртывания рабочих баз.

## Сделано

- [x] Задачи 1–6 (1С, комплектация, копирование товаров и ранее согласованные изменения) слиты в PR #147. Наличие кода не означает автоматическое развёртывание.
- [x] Отдельные SQL-миграции сохраняются в `supabase/migration_*.sql` и включены в `supabase/FULL_DATABASE_MIGRATION.sql`.
- [x] Подключение двух Supabase с разными ключами и ручной выбор источника. Шаблон окружения описывает целевое расположение: Beget — #1, supabase.com — #2. Существующие реальные значения не изменялись.
- [x] Владелец может быть добавлен через Supabase Table Editor, без обязательного запуска CLI или ручного SQL. Вход, роли и диагностика базы.
- [x] Полные снимки `public`-таблиц, ручной экспорт, ограниченное периодическое копирование между Supabase и восстановление с подтверждением. Не включают Supabase Auth, Storage и внешние файлы; отсутствие потерь не гарантируется.
- [x] Серверные архивы Timeweb и старое серверное зеркалирование отключены; ранее существовавшие файлы и неподтверждённые изменения не удалены.
- [x] Без выбранной папки браузер запрашивает загрузку копии и хранит текущий снимок в IndexedDB профиля; запрос загрузки не подтверждает фактическое сохранение. Без подготовленного журнала обновления не отслеживаются. Проверено только имитацией браузера, не развёрнуто.
- [x] Отдельные каталоги на ПК, браузерные архивы Supabase в 18:00 и 23:00 Новосибирска, ручной экспорт и экспериментальный журнал изменений с опросом около 5 секунд при открытой вкладке владельца. Требуются установленные миграции, подготовленные триггеры, разрешения, сеть и поддерживаемый браузер.
- [x] Выбор и смена существующей папки, включая Z:, вручную в админке локального сервера; старая копия и архивы не удаляются. Сам диск заранее подключается в Windows, реальный SMB пока не проверен.
- [x] Экспериментальный локальный сервер ПК: выбор папки, парольный офлайн-вход и просмотр части данных, отдельная сессия, режим только чтения, отказ без подмены файла при ошибке и явные предупреждения.
- [x] Опциональное обновление чистого локального снимка при доступной выбранной Supabase, с проверкой идентификатора источника, версий и изменений. Не перезаписывает JSON при отсутствии изменений и не заменяет файл при обнаруженных независимых изменениях. Работает только при открытой админке владельца на локальном сервере.
- [x] Отдельные архивы локального снимка в 18:00/23:00 при работающем локальном сервере, в том числе офлайн, с отказом от перезаписи и сообщением об ошибке. Окно — 10 минут; hard link и сетевые диски нуждаются в реальной проверке.
- [x] Неоднозначная запись при обрыве не повторяется автоматически на другом Supabase. Автоматически выбранный резерв доступен через адаптер только для чтения до явного выбора владельцем; актуальность резерва не гарантируется.
- [x] Добавлен отдельный экспериментальный SQL-примитив транзакционной проверки и применения на одном источнике с квитанцией повторного вызова; он не подключён к интерфейсу, ограничен 500 строками и не доказан на реальном PostgreSQL.
- [x] Предварительный трёхсторонний план по первичным ключам и более консервативное объединение снимков по таблицам. Это проверка/подготовка, не автоматическое применение изменений.

- [ ] Испытания на реальных Beget и supabase.com, Windows, сетевом Z:/SMB, потере питания, параллельных процессах на разных ПК и производительности больших JSON-файлов.
