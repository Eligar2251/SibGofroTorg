# Производительность: что сделано и что дальше

Цель — «чтобы всё летало» на мониторах 120 Гц. Ниже: что уже сделано, реальные
замеры и приоритизированный список дальнейших шагов с честной оценкой риска.

## 2. Замеры (сборка `pnpm build`)

```
.next/static/chunks         3.8 МБ всего
  464 КБ   WarehouseManager  ← модуль «Учёт», один кусок
  448 КБ   общий вендорный чанк
  224 КБ
  196 КБ   html2canvas       ← уже грузится лениво, только при печати
CSS
  272 КБ   admin.css и соседи (33 500 строк)
  128 КБ
  108 КБ
```

Что уже сделано правильно и трогать не надо:
- CSS админки подключён в `layout` админки, а не в корневом — посетители сайта
  эти 272 КБ не скачивают;
- тяжёлые библиотеки (`html2canvas`, `@zxing`) импортируются динамически;
- `xlsx` используется только на сервере и в браузер не попадает;
- все слушатели `scroll`/`resize` — `passive`;
- в `admin.css` уже есть секция «ПРОИЗВОДИТЕЛЬНОСТЬ 60–120 FPS» с
  `content-visibility` для дашборда и списка заявок.

Осталось из безрискового:

5. ✅ **`contain: content`/`content-visibility: auto` на повторяющихся карточках** —
   сделано (`.admin-order`, `.bank-pay`, `.rent-row`, строки дашборда, карточки

### Средний риск, самый большой выигрыш

5. ✅ **«Учёт» разбит на вкладки через `next/dynamic`** — сделано.
   Было: один клиентский чанк на 464 КБ, браузер парсил и гидрировал все
   вкладки, даже открыв одну. Стало: **232 КБ**, остальное подтягивается
   в момент открытия вкладки. Лениво грузятся зарплаты, автораспределение
   ЗП, отчёты, перевозки, планы поставок, закупки, прогноз, план продаж,
   клиенты, товар на реализации, ревизия склада и модалка инкассации —
   всё это и раньше рендерилось только при активной вкладке, поэтому
   поведение не изменилось.

   Побочный эффект, ради которого это и пришлось делать срочно: dev-сервер
   падал на компиляции этой страницы с «JavaScript heap out of memory»
   в воркере Turbopack. Теперь компилируется за ~4 секунды.
6. ✅ **Оконный рендеринг длинных списков** (`use-windowed-list`) — сделано
   для самых тяжёлых мест: каталог товаров (десктоп-таблица и телефон-карточки)

   Остались: сделки/платежи «Учёта» (`/warehouse`) — там же готовый хук.
7. **Серверная пагинация вместо «загрузить всё».** Страница `/warehouse` на каждый

   перевозки, инкассации, планы, плюс 500 заказов и 200 пользователей. Это и время

8. **Разбить `admin.css`** (33 500 строк) по маршрутам — сейчас все стили всех

### Точечно под 120 Гц

9. ✅ **Авто-пресет «Производительность» на слабых устройствах** — сделано.
   `adminThemeInitScript` (до первой отрисовки) и `AdminTheme` включают
   `data-admin-anim="reduced"` без участия пользователя, если видят
   `matchMedia('(update: slow)')`, `prefers-reduced-motion`,
   `navigator.hardwareConcurrency <= 4` или `navigator.deviceMemory <= 4`.
   Режим теперь гасит не только анимации, но и все `backdrop-filter` админки.
   Явный выбор в Настройках сохраняется в localStorage и всегда главнее;
   «Сбросить» возвращает авто-режим по устройству.
10. **Проверить длительности анимаций.** Всё, что длится 0.2–0.3 с на
    `transform/opacity`, на 120 Гц выглядит отлично; проблема возникает только у
    анимаций `width/height/top/left` — в текущем CSS таких в ключевых кадрах нет,
    но при добавлении новых стоит держать правило «только transform и opacity».

## 3.1. Память dev-сервера

`pnpm dev` запускается через `scripts/dev.mjs`, который поднимает кучу Node
до 8 ГБ (`NODE_OPTIONS=--max-old-space-size`). Именно переменной окружения,
а не флагом: воркеры Next наследуют окружение, но не флаги родителя.

Переопределить: `SGT_DEV_MEMORY=12288 pnpm dev`.
Запустить без обёртки: `pnpm dev:plain`.

## 4. Чего делать НЕ надо

- **Не возвращать библиотеки «плавного скролла»** (lenis, locomotive и подобные).
  Нативная прокрутка в браузере уже синхронизирована с частотой монитора и на
  120 Гц идёт в 120 кадров. Любая JS-интерполяция это ломает.
- **Не расставлять `will-change` «на всякий случай»** — каждый такой элемент это
  отдельный слой композитора. Оправдан он только для одного-двух элементов,
  которые действительно анимируются постоянно (сейчас это сайдбар админки).
- **Не добавлять `backdrop-filter` к `fixed`/`sticky` элементам** — самый дорогой
  эффект при прокрутке.
