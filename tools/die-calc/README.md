# Калькулятор штанцформы — `tools/die-calc`

Считает **гофроупаковку по внутренним размерам коробки**: сама строит развёртку,
печатает SVG-чертёж штампа и DXF для ЧПУ, показывает сборку в 3D, раскладывает
заготовки по листу и считает деньги (штамп + тираж).

Ядро — чистый TypeScript без зависимостей (`src/core`), интерфейс — React 18/19
(`src/ui`). **Никакого Supabase/бэкенда не требуется**: всё состояние живёт в
`localStorage`, расчёты идут на клиенте. Ядро можно вызывать и на сервере
(API-роут, батч-прайс, генерация превью).

## Что именно считается

| Выход | Откуда берётся |
|---|---|
| Габарит заготовки `W×H` | по **краям коробки** (контур высечки), а не по штампу |
| Площадь заготовки | площадь полигона контура (м²) — по ней цена картона |
| Штамп | заготовка + `frameMargin` (у вас 40 мм) с каждой стороны, `n`-уп + `diePitch` |
| Длины ножей | рез / биговка / перфорация / техно-уголки, м + длина стали с перемычками |
| Раскладка | штуки с листа, листов на тираж, полезный выход, % |
| Цена | комплектующие штампа (фанера, лазер, ножи, гибка, резина, наценка) и тираж (картон, высечка, упаковка, наладка, маржа, НДС) |
| «Как считалось» | построчный вывод всех припусков и формул — чтобы сверить с чертежом |

Формула габарита («звезда», как в ваших чертежах):

```
blankW = sSide + Hp + Lp + Hp + sSide (+ клеевой клапан)
blankH = sFront + Hf + Wp + Hp + sBack + выступ замка (sTab)
```

`Lp/Wp/Hp` — панели с припуском на толщину гофры, длины клапанов — из
`Coef.flaps[закрытие]` (`src/core/model.ts`). Все коэффициенты редактируются в
UI на вкладке «Настройки и цены» → «Припуски», и их можно подогнать по своим
чертежам кнопкой «Автоподгонка».

## Конструкции и закрытия

Четыре конструкции (пока только они):

1. **«Ласточкин хвост»** — 4 клапана + ушки, самый ходовой самосбор.
2. **«С замком-язычком»** — язычок входит в паз передней стенки.
3. **«Лоток»** — три стенки, передняя ниже (`frontK`), без клапанов.
4. **«Боковой замок»** — клапаны складываются внахлёст сбоку.

Плюс режим **«по чертежу матрицы»**: вводите габарит заготовки руками, движок
строит рамку, считает площадь, раскладку, ножи и цену (для форм, шаблона
которых ещё нет).

Закрытие — отдельный выбор: `none / half / tuck / full / glue`. Для каждого —
своё правило длины клапанов, его можно подогнать отдельно.

### Своя штанцформа

Во вкладке **«Своя форма»** можно начертить развёртку в миллиметрах, не выбирая
готовую конструкцию:

* рисовать открытые линии реза, биговки, перфорации и технологические линии;
* создавать замкнутые внешние контуры и внутренние вырезы, задавать размеры;
* вставить редактируемый шаблон лотка с ушками или начать с пустого листа;
* загрузить фото/скан как временную подложку, откалибровать масштаб по известному
  отрезку и обвести контур; подложка не включается в заказ и экспорт;
* отменять/повторять действия, масштабировать рабочую область, импортировать и
  экспортировать проект в JSON.

Геометрия передаётся обычному расчёту листа, ножей, штампа и стоимости. Площадь
считается по внешним контурам минус вырезы; для сложной формы её можно указать
вручную — размеры и метраж ножей при этом остаются по начерченным линиям.
Чертёж хранится вместе с заданием в `settings.customDrawing` и восстанавливается
при повторном открытии. DXF/SVG содержат отдельные слои реза, биговки,
перфорации, TECH и размеров.

## Точность по вашим 9 чертежам

Дефолты в `model.ts` **уже подогнаны** по 6 чертежам, которые поддаются
описанию текущими шаблонами (`npm run check` пересчитывает сверку):

| чертёж | факт W×H | расчёт | Δ |
|---|---|---|---|
| 0427 240×180×60 E (ласточкин+язычок) | 550×513 | 550×513 | **0 / 0** |
| 0470 240×180×60 E (боковой замок) | 610×518 | 610×518 | **0 / 0** |
| 0427 240×180×60 E, печать (язычок) | 548,5×503 | 550×513 | +1,5 / +10 |
| 0436 380×280×60 B (лоток) | 666×480 | 670×480,5 | +4 / +0,5 |
| 0436 255×190×60 B (лоток) | 513×400 | 495×364 | −18 / −36 |
| 0427 125×110×115 E (ушки) | 575×618 | 531×474 | −44 / −144 |

Не калибруются (нет шаблона): 0470-235×103×60 (лоток + гильза, две разные детали
на штампе), 0427-100×100×350 (длинный пенал, нужна расшифровка), 0215-90×90×120
(крышки встык). Правила закрытия «ушки» (`half`) сознательно **не** запечены —
его тянет единственный чертёж и получается нефизично; подгоните, когда появится
второй.

## API (без React)

```ts
import { quickEstimate, calcBox, baseSettings, makeInput, toDxf, renderUnfold, specText } from './core';

// в одну строку — для прайса/каталога
const q = quickEstimate({ L: 240, W: 180, H: 60, profile: 'E', construction: 'lastochkin', closure: 'tuck', qty: 5000 });
// q.blank = { w: 550, h: 513, areaM2: 0.2822, polyAreaM2: 0.1823 }
// q.sheet = { name: '1800×2400', perSheet: 12, utilization: 0.506, sheets: 417 }
// q.price = { die: 6909, batch: 144370, perPcs: 28.87, ... }

// полный результат + чертежи
const res = calcBox({ input: makeInput({ L: 240, W: 180, H: 60, profile: 'E' }), settings: baseSettings() });
const svg = renderUnfold(res, { theme: 'light', showDie: true, showDims: true, showFills: true });
const dxf = toDxf(res, { label: '0427-240*180*60-E' });
const txt = specText(res, '0427');
```

Цены и профили — в `src/core/model.ts` (`DEFAULT_PROFILES[].priceM2`: микрогофра
E = 36 ₽/м², B = 38 ₽/м²; `DEFAULT_PRICES` — всё остальное). Форматы листа —
`DEFAULT_SHEETS`.

## Что показано на экране

* **Развертка** = только **вырезанная заготовка** коробки: контур реза, биговка,
  перфорация, вырезы замка и размеры. Плита штампа (рамка, техно-уголки, рамка
  маркировки) по умолчанию скрыта — включается чекбоксом «как штамп» (он же
  включает рамку в SVG/PNG; `npm run preview:svg` кладёт рядом `-die.png`).
* **Сборка 3D** = та же коробка: дерево панелей гнётся вокруг линий биговки,
  каждый клапан держится за своего родителя, послойный зазор 0,035 мм на шаг
  сборки — поэтому перехлёсты лежат друг на друге, а не «мерцают» и не висят
  в воздухе. Свойство закреплено тестом (`npm test` → «панели соединены по
  линиям сгиба»): линия сгиба каждой панели лежит на контуре родителя, общий
  край в сборке расходится меньше чем на 1,6 мм, стенки вертикальны, крышка
  лежит на стенках на высоте Hp.
* **Раскладка по листу** — штуки с листа в двух ориентациях + гильотинные
  комбинации, цвет по остаткам.

## Где это в сайте

Расчёт живёт **только в админке**: `/[adminPath]/die-calc` (пункт меню
«Штанцформа», иконка-ножовка; доступен admin/owner/manager, юристу и
макулатурщику — нет, см. `canAccessAdminPage`). Публичных страниц нет,
`src/app/(сайт)` не тронут.

В приложении лежат **копии**, которые генерирует скрипт:

| в сайте | откуда |
|---|---|
| `src/lib/die-calc/**` | `tools/die-calc/src/core/**` |
| `src/components/admin/die-calc/**` | `tools/die-calc/src/ui/**` |
| `src/app/admin-die-calc.css` | `tools/die-calc/src/ui/ui.css` |

```bash
cd tools/die-calc && npm run sync:site    # перенести правки в приложение
npm run sync:check                          # проверка, что копии не отстали
```

Скрипт меняет только пути импортов (`../core/x` → `@/lib/die-calc/x`,
`./ui.css` → `@/app/admin-die-calc.css`) и ставит сверху баннер «не правьте в
src/». Стили калькулятора полностью под `.dgc-root`, глобальных селекторов
(`body`, `*`, `@page`) там нет — вёрстку админки не трогают. Проверено
`node_modules/.bin/tsc --noEmit`, `eslint` и `next build` (роут
`ƒ /[adminPath]/die-calc` собирается).

### Если нужен второй вход (свой сайт, прайс, мобильное приложение)

Копируете те же папки (`core` + `ui`), ставите `'use client'`-обёртку и
рендерите `<DieCalc />`. Зависимости — только `react`/`react-dom`. Для
расчёта на сервере ядро вызывается напрямую:

```ts
import { quickEstimate } from '@/lib/die-calc';
const q = quickEstimate({ L: 240, W: 180, H: 60, profile: 'E', construction: 'lastochkin', closure: 'tuck', qty: 5000 });
```

Связка с базой — `packJob(res, {...})` из `src/core/learn.ts`: он собирает
колонки строки `die_calc_jobs` + `settings`/`result` в `jsonb` (того же
содержания, что и `resultJson(res)` из `src/components/admin/die-calc/exports.ts`),
а `jobToPatch(row)` разворачивает строку обратно в состояние калькулятора.
В самом ядре Supabase-вызовов нет — см. следующий раздел.

## Сохранение расчётов и обучение (таблицы `die_calc_*`)

По умолчанию калькулятор считает «в экран»: состояние и ставки лежат в
localStorage браузера. Чтобы расчёты стали журналом и начали заодно учить
программу, нужна одна миграция — `supabase/migration_die_calc.sql`:

| таблица | что лежит |
|---|---|
| `die_calc_jobs` | сохранённые расчёты: ввод (размеры, конструкция, замок, профиль, тираж), посчитанные габарит/штамп/ножи/цена, **факт** (`fact_*` — замер с готовой матрицы и согласованная цена) и `settings`/`result` jsonb для точного повтора |
| `die_calc_models` | выученные модели: активная строка + история (есть чем откатить неудачную подгонку) |
| `die_calc_settings` | общий прайс: профили, форматы листа, ставки — чтобы у всех считалось по одним цифрам |
| `die_calc_job_stats` (вьюха) | среднее по группам: записей, с фактом габарита/цены, средняя ошибка мм, средний множитель цены |

Порядок работы:

1. Посчитали коробку → вкладка **«База и обучение»** → «сохранить в базу».
   В строку уходит всё для повтора: ввод, опции, ваши коэффициенты, ставки и
   снимок результата.
2. Штамп сделали, заготовку померили, цену согласовали — те же поля заполняются
   в блоке «Факт» (или в журнале «Расчёты штанцформ»). Пока факта нет, запись
   в обучение не попадает; флажок «в обучении» выключает конкретную строку,
   не удаляя её.
3. **«Обучить по базе»** → `learnModel()` из `src/core/learn.ts`:
   * *геометрия* — подтверждённые строки конструкции превращаются в `Fixture`
     и по ним подгоняется таблица припусков (`fitCoef`, тот же координатный
     спуск, что и на вкладке «Калибровка»). Старт — от коэффициента самой
     свежей записи группы, поэтому обучение накапливается и не затирает ручную
     подгонку. Если подгонка не улучшила ошибку — коэффициенты не меняются.
   * *цена* — медиана отношения «факт/расчёт» по группе
     «конструкция × замок × профиль», с отбросом выбросов по MAD; если группы
     нет, берется уровень «вся конструкция», затем «весь прайс».
4. Дальше новая коробка того же типа считается уже по выученным припускам:
   развертка, 3D, DXF и габарит штампа берутся из них — «матрица» получается
   как в цехе, а не «примерно». Рядом с ценой показывается «по ставкам» и «по
   обучению ×1.0x»; чекбокс «применять» выключает поправку целиком.

В сайте за это отвечают: `src/lib/die-calc-db.ts` (чтение/запись, белый список
колонок, `trainDieCalcModel`), `src/app/api/admin/die-calc/**` (`GET`/`POST`,
`[id]` — `PATCH`/`DELETE`, `train`, `settings`), `DieCalcWorkbench.tsx`
(слот «База и обучение» внутри `<DieCalc>`) и `DieCalcJobsClient.tsx`
(журнал-таблица: правка размеров, статуса, цен и фактов прямо в строке).
Механика — `props.slots` у `<DieCalc />`: ядро и UI песочницы остаются без
Supabase, `slots` просто не передаются, и `npm run dev` работает как раньше.

## Калибровка по чертежам

Приоритет источников: **DXF (1:1, мм) > PDF с размерами > скан**. DXF можно
читать тем же `toDxf`-форматом: слои `CUT` (рез), `CREASE` (биговка), `PERF`
(перфорация), `TECH` (техно-уголки), `MARK` (рамка и маркировка). По DXF видно
реальную цепочку панелей, поэтому расхождение с моделью измеряется в доли
миллиметра, а не в «на глаз по скану».

Быстрый путь без DXF: вкладка **«Калибровка»** → «Добавить эталон» (внутренние
L×W×H, профиль, конструкция, закрытие, габарит заготовки с чертежа) →
**«Автоподгонка»**. Она правит только припуски и правила клапанов, показывает
Δ до/после по каждому чертежу и позволяет сохранить coef-ы в `model.ts`
(`npm run check`, секция 7, печатает готовый JSON для дефолтов).

## Что можно крутить

* `Coef` по конструкции: припуски панелей (`allowL/W/H`: `k·размер + c + kt·t`),
  ушки/язычок/радиус скругления/нахлёст/клеевой клапан, высота передней стенки
  (`frontK`), вырез лотка (`frontCut`), правила клапанов по каждому закрытию.
* `Options`: ручка, двойная биговка, перфорация, техно-углы, зеркало,
  `perDie` (2-up/3-up — ножи и лазер считаются по всем гнёздам), `diePitch`.
* `NestingSettings`: зазоры, отступ от края листа, минимальная сторона остатка.
* `DieSettings`: `frameMargin` (40 мм), длина техно-угла, ник/перемычки.

## Известные ограничения

* Длины ножа по модели на 3–20% ниже чертёжных: на штампе ножи ставят с запасом
  и общими участками — для расчёта стоимости это консервативно в плюс.
* 3D-сборка — иллюстративная: ортография со слабой перспективой, без физики
  самосбора (углы всегда ровно `fold` градусов, без пружинения гофры).
* DXF — R12, скругления нарезаны короткими `LINE` (R12 не умеет LWPOLYLINE с
  дугами); открывается в AutoCAD/LibreCAD/Rhino/VisorCAM.
* Площадь заготовки — по контуру высечки; в листе считается «слот» (габарит),
  потому что картон режется листами и отходы (`waste`) тоже оплачиваются.
