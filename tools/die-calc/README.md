# Калькулятор штанцформы — `tools/die-calc`

Считает **гофроупаковку по внутренним размерам коробки**: сама строит развёртку,
печатает SVG-чертёж штампа и DXF для ЧПУ, показывает сборку в 3D, раскладывает
заготовки по листу и считает деньги (штамп + тираж).

Ядро — чистый TypeScript без зависимостей (`src/core`), интерфейс — React 18/19
(`src/ui`). **Никакого Supabase/бэкенда не требуется**: всё состояние живёт в
`localStorage`, расчёты идут на клиенте. Ядро можно вызывать и на сервере
(API-роут, батч-прайс, генерация превью).

## Что именно считается

| Выход | Откуда берётся |
|---|---|
| Габарит заготовки `W×H` | по **краям коробки** (контур высечки), а не по штампу |
| Площадь заготовки | площадь полигона контура (м²) — по ней цена картона |
| Штамп | заготовка + `frameMargin` (у вас 40 мм) с каждой стороны, `n`-уп + `diePitch` |
| Длины ножей | рез / биговка / перфорация / техно-уголки, м + длина стали с перемычками |
| Раскладка | штуки с листа, листов на тираж, полезный выход, % |
| Цена | комплектующие штампа (фанера, лазер, ножи, гибка, резина, наценка) и тираж (картон, высечка, упаковка, наладка, маржа, НДС) |
| «Как считалось» | построчный вывод всех припусков и формул — чтобы сверить с чертежом |

Формула габарита («звезда», как в ваших чертежах):

```
blankW = sSide + Hp + Lp + Hp + sSide (+ клеевой клапан)
blankH = sFront + Hf + Wp + Hp + sBack + выступ замка (sTab)
```

`Lp/Wp/Hp` — панели с припуском на толщину гофры, длины клапанов — из
`Coef.flaps[закрытие]` (`src/core/model.ts`). Все коэффициенты редактируются в
UI на вкладке «Настройки и цены» → «Припуски», и их можно подогнать по своим
чертежам кнопкой «Автоподгонка».

## Конструкции и закрытия

Четыре конструкции (пока только они):

1. **«Ласточкин хвост»** — 4 клапана + ушки, самый ходовой самосбор.
2. **«С замком-язычком»** — язычок входит в паз передней стенки.
3. **«Лоток»** — три стенки, передняя ниже (`frontK`), без клапанов.
4. **«Боковой замок»** — клапаны складываются внахлёст сбоку.

Плюс режим **«по чертежу матрицы»**: вводите габарит заготовки руками, движок
строит рамку, считает площадь, раскладку, ножи и цену (для форм, шаблона
которых ещё нет).

Закрытие — отдельный выбор: `none / half / tuck / full / glue`. Для каждого —
своё правило длины клапанов, его можно подогнать отдельно.

## Точность по вашим 9 чертежам

Дефолты в `model.ts` **уже подогнаны** по 6 чертежам, которые поддаются
описанию текущими шаблонами (`npm run check` пересчитывает сверку):

| чертёж | факт W×H | расчёт | Δ |
|---|---|---|---|
| 0427 240×180×60 E (ласточкин+язычок) | 550×513 | 550×513 | **0 / 0** |
| 0470 240×180×60 E (боковой замок) | 610×518 | 610×518 | **0 / 0** |
| 0427 240×180×60 E, печать (язычок) | 548,5×503 | 550×513 | +1,5 / +10 |
| 0436 380×280×60 B (лоток) | 666×480 | 670×480,5 | +4 / +0,5 |
| 0436 255×190×60 B (лоток) | 513×400 | 495×364 | −18 / −36 |
| 0427 125×110×115 E (ушки) | 575×618 | 531×474 | −44 / −144 |

Не калибруются (нет шаблона): 0470-235×103×60 (лоток + гильза, две разные детали
на штампе), 0427-100×100×350 (длинный пенал, нужна расшифровка), 0215-90×90×120
(крышки встык). Правила закрытия «ушки» (`half`) сознательно **не** запечены —
его тянет единственный чертёж и получается нефизично; подгоните, когда появится
второй.

## Команды

```bash
cd tools/die-calc
npm install
npm run dev          # standalone-превью на :5173 (0.0.0.0)

npm test             # 31 тест: геометрия, раскладка, деньги, экспорт
```

## API (без React)

```ts
import { quickEstimate, calcBox, baseSettings, makeInput, toDxf, renderUnfold, specText } from './core';

// в одну строку — для прайса/каталога
const q = quickEstimate({ L: 240, W: 180, H: 60, profile: 'E', construction: 'lastochkin', closure: 'tuck', qty: 5000 });
// q.blank = { w: 550, h: 513, areaM2: 0.2822, polyAreaM2: 0.1823 }
// q.sheet = { name: '1800×2400', perSheet: 12, utilization: 0.506, sheets: 417 }
// q.price = { die: 6909, batch: 144370, perPcs: 28.87, ... }

// полный результат + чертежи
const res = calcBox({ input: makeInput({ L: 240, W: 180, H: 60, profile: 'E' }), settings: baseSettings() });
const svg = renderUnfold(res, { theme: 'light', showDie: true, showDims: true, showFills: true });
const dxf = toDxf(res, { label: '0427-240*180*60-E' });
const txt = specText(res, '0427');
```

Цены и профили — в `src/core/model.ts` (`DEFAULT_PROFILES[].priceM2`: микрогофра
E = 36 ₽/м², B = 38 ₽/м²; `DEFAULT_PRICES` — всё остальное). Форматы листа —
`DEFAULT_SHEETS`.

## Вставка в Next.js (App Router)

1. Скопировать папку целиком, например в `src/features/die-calc/`:

```bash
cp -r tools/die-calc/src/core tools/die-calc/src/ui src/features/die-calc/
cp tools/die-calc/src/ui/ui.css src/features/die-calc/ui/ui.css   # уже внутри
```

   Нужны только `core/` и `ui/` — `test/`, `scripts/`, `index.html`, `vite.config.mjs`
   в приложение не копируются.

2. Никаких npm-зависимостей не добавлять: `react`, `react-dom` уже есть,
   `package.json` тулзы — только для standalone-режима.

3. Страница (`src/ui/DieCalc.tsx` помечен `'use client'`, поэтому серверная
   обёртка не трогает расчёты на сервере):

```tsx
// src/app/kalkulyator-shtancformy/page.tsx
import { DieCalc } from '@/features/die-calc/ui/DieCalc';

export const metadata = { title: 'Калькулятор штанцформы — СибГофроТорг' };

export default function Page() {
  return <DieCalc tab="unfold" initial={{ L: 240, W: 180, H: 60, profileId: 'E' }} />;
}
```

   Если нужен ленивый импорт (тяжёлый SVG на больших тиражах):

```tsx
'use client';
import dynamic from 'next/dynamic';
const DieCalc = dynamic(() => import('@/features/die-calc/ui/DieCalc').then((m) => m.DieCalc), { ssr: false });
```

4. Стили. `DieCalc.tsx` сам импортирует `./ui.css` (обычный CSS-модуль не
   используется, селекторы в префиксе `.dgc-`, так что Tailwind v4 их не
   перекроет). Если сборка заропщет на импорт CSS из компонента —
   `import '@/features/die-calc/ui/ui.css';` в `app/layout.tsx`.

5. Тёмная тема/подложка: `<DieCalc dark />` или обернуть в свой контейнер —
   переменные `--dgc-*` можно переопределить в глобальных стилях, цвета бренда
   подхватываются из `globals.css` (`--green`).

6. **Связка с корзиной.** Готовый объект для позиции:

```tsx
import { resultJson } from '@/features/die-calc/ui/exports';   // сериализация расчёта
// или соберите сами:
const line = {
  sku: `ШТ-${res.area.blankW}x${res.area.blankH}`,
  qty: res.input.qty,
  price: res.cost.perPcs,          // ₽/шт без оснастки
  withDie: res.cost.perPcsWithDie, // ₽/шт с амортизацией штампа
  note: `${res.input.L}×${res.input.W}×${res.input.H}, ${profile.flute}, ${construction.name}`,
};
```

   Заказ/Супабейз — по желанию: сохраните `resultJson(res)` в `jsonb`-колонку,
   чтобы пересобрать чертёж и цену позже по той же точке. В самом калькуляторе
   запросов к бэкенду нет.

## Калибровка по чертежам

Приоритет источников: **DXF (1:1, мм) > PDF с размерами > скан**. DXF можно
читать тем же `toDxf`-форматом: слои `CUT` (рез), `CREASE` (биговка), `PERF`
(перфорация), `TECH` (техно-уголки), `MARK` (рамка и маркировка). По DXF видно
реальную цепочку панелей, поэтому расхождение с моделью измеряется в доли
миллиметра, а не в «на глаз по скану».

Быстрый путь без DXF: вкладка **«Калибровка»** → «Добавить эталон» (внутренние
L×W×H, профиль, конструкция, закрытие, габарит заготовки с чертежа) →
**«Автоподгонка»**. Она правит только припуски и правила клапанов, показывает
Δ до/после по каждому чертежу и позволяет сохранить coef-ы в `model.ts`
(`npm run check`, секция 7, печатает готовый JSON для дефолтов).

## Что можно крутить

* `Coef` по конструкции: припуски панелей (`allowL/W/H`: `k·размер + c + kt·t`),
  ушки/язычок/радиус скругления/нахлёст/клеевой клапан, высота передней стенки
  (`frontK`), вырез лотка (`frontCut`), правила клапанов по каждому закрытию.
* `Options`: ручка, двойная биговка, перфорация, техно-углы, зеркало,
  `perDie` (2-up/3-up — ножи и лазер считаются по всем гнёздам), `diePitch`.
* `NestingSettings`: зазоры, отступ от края листа, минимальная сторона остатка.
* `DieSettings`: `frameMargin` (40 мм), длина техно-угла, ник/перемычки.

## Известные ограничения

* Длины ножа по модели на 3–20% ниже чертёжных: на штампе ножи ставят с запасом
  и общими участками — для расчёта стоимости это консервативно в плюс.
* 3D-сборка — иллюстративная (ортографическая, без физики самосбора).
* DXF — R12, скругления нарезаны короткими `LINE` (R12 не умеет LWPOLYLINE с
  дугами); открывается в AutoCAD/LibreCAD/Rhino/VisorCAM.
* Площадь заготовки — по контуру высечки; в листе считается «слот» (габарит),
  потому что картон режется листами и отходы (`waste`) тоже оплачиваются.
