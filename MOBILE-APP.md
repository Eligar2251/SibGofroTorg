# 📱 Мобильная админка «как нативное приложение» + PWA

Обновление поверх PR #81 (аудит — в `MOBILE-AUDIT.md`).
Дата: 09.09.2026 · Ветка: `arena/01a083da-sibgofrotorg`

---

## Что изменилось по сути

Раньше телефон получал **ужатый десктоп**: сервер рендерил сайдбар,
тулбар и таблицы, а 3,7 тыс. строк `admin-mobile.css` с `!important`
пытались превратить это в мобильный вид — отсюда «всё съезжает
и криво».

Теперь телефон (≤768px) получает **полностью отдельный интерфейс**,
а десктопная разметка на нём вообще не рендерится:

| Слой | Было (PR #81) | Стало |
|---|---|---|
| Оболочка | десктопная разметка + CSS-переопределения | `MobileAdminShell` — свой каркас: шапка приложения + нижние вкладки |
| Навигация | заголовок + бургер + ящик-меню | нижняя панель вкладок (Панель · Заявки · Товары · Учёт · Ещё) + лист «Ещё» со всеми разделами |
| Заявки | «details»-строки десктопа, ужатые CSS | `OrdersMobile` — карточки: номер, чипы статуса, кнопка звонка, позиции, действия |
| Товары | таблица 8 колонок, ужатая CSS | `ProductsMobile` — карточки с фото/ценой/остатком + фильтры нижним листом |
| Дашборд | только десктопные блоки | `DashboardMobileTop` — плитки показателей + быстрые действия |
| Модалки | как в PR #81 (скролл исправлен) | без изменений — работают поверх новой оболочки через `#admin-modal-root` |

## Новые файлы (мобильный слой — десктопные не тронуты)

```
src/components/admin/mobile/
  MobileAdminShell.tsx / .module.css   — оболочка приложения
  MobileTabBar.tsx / .module.css       — нижние вкладки + лист «Ещё»
  ProductsMobile.tsx / .module.css     — товары карточками
  HideOnMobile.tsx                     — прячет десктопный блок на телефоне
src/app/[adminPath]/
  DashboardMobileTop.tsx / .module.css — плитки дашборда
  orders/OrdersMobile.tsx / .module.css — заявки карточками
src/lib/orders-labels.ts               — общие подписи статусов (десктоп+мобилка)
src/hooks/use-is-mobile.ts             — + useIsPhone() (≤768px — граница новой оболочки)
```

**Медиазапросов в новых файлах нет** — «мобильность» определяет
JS-хук (`useIsPhone`/`useIsMobile`), а не брейкпоинт. Стили — CSS-модули.

**Десктоп не меняется** — проверено автоматически: DOM ключевых
страниц (главная, дашборд, заявки, товары, клиенты) на 1440px
**побайтово совпадает** с веткой `main`; единственное отличие —
один дополнительный `<link rel="stylesheet">` (CSS новых
компонентов). Планшеты 769–1024px остались на прежней панели.

## Правила слоёв (для будущих страниц)

- Контент страницы переключается хуком:
  `const isMobile = useIsMobile(); … isMobile ? <Mobile/> : <Desktop/>`.
- Мобильный компонент лежит **рядом с оригиналом**, стили —
  CSS-модуль, без медиазапросов.
- Анимации — только `transform`/`opacity` (композитор, 90–120 Гц).
  Анимировать `height/top/left/width` нельзя — это layout, на 120 Гц
  «дёргается».
- Длинные списки — `content-visibility: auto; contain-intrinsic-size`
  (браузер не рисует карточки за экраном).
- Кнопки — от 40–44px, `touch-action: manipulation`,
  `-webkit-tap-highlight-color: transparent`.
- Отступы — `env(safe-area-inset-*)` для «чёлки» и жестовой полосы.

## 120 Гц / плавность

- Все переходы новой оболочки — композиторные: листы выезжают
  `translateY` с кривой `cubic-bezier(0.32, 0.72, 0.16, 1)`,
  нажатия — `scale(0.92–0.97)`, затемнения — `opacity`.
- `overscroll-behavior: contain` у листов — «резиновый» скролл iOS
  не тянет страницу под листом.
- Пульс realtime-точки и индикаторы — уже были на `transform/opacity`.
- `useDeferredValue` в поиске заявок/товаров: ввод не блокируется
  перерисовкой списка.

## PWA (убрать панели браузера)

Было настроено в PR #81 и дополнено здесь:

- `/manifest.webmanifest` (сайт) и `/admin-manifest.webmanifest`
  (админка): `display: "standalone"`, иконки 192/512 + maskable.
- iOS: `apple-mobile-web-app-capable`, `black-translucent`,
  `viewport-fit=cover` — в `<head>` через metadata Next.js.
- `/sw.js` и `/admin-sw.js` — **добавлен пустой обработчик `fetch`**
  (без `respondWith`): старые Chrome до ~126 не показывали кнопку
  «Установить», если у worker'а нет обработчика fetch. Ничего не
  кешируется.
- Проверено в headless-браузере: worker регистрируется, manifest
  подключён, иконки отдаются (200).

**Как увидеть на телефоне:** открыть сайт по HTTPS → меню браузера →
«Добавить на главный экран» / «Установить приложение» → иконка на
рабочем столе открывает админку **без адресной строки и панелей
браузера**. Один раз согласиться с cookie-баннером (он поверх всего).

## Как это проверялось

Без доступа к прод-БД: локальный мок Supabase (пустые ответы) +
прод-сборка + headless Chromium 375×812 (iPhone X) с подписанной
сессией `admin`:

- **28 автопроверок — все PASS**: геометрия шапки (fixed, 56px) и
  вкладок (fixed, 5 шт., правильная активная), отсутствие
  сайдбара/бургера/старой панели, `data-admin=true`, нет
  горизонтального оверфлоу (375=375), кружки-индикаторы внутри
  шапки, лист «Ещё» (открытие/Escape/сетка 16 разделов), SW+manifest,
  плитки дашборда, планшет (769px) и десктоп (1280px) без изменений.
- Ни одной JS-ошибки в консоли.
- Скриншоты: `shots/01…11` (доступны в артефактах проверки).
